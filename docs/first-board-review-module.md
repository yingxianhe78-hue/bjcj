# 首板复盘模块设计

## 目标

围绕“北京炒家”交易体系，建立每日首板复盘模块，用于自动筛出当日首板个股，并整理成交额、封板强度、炸板情况和次日观察池。

模块核心不是单纯列涨停股，而是帮助回答三个问题：

1. 今天市场第一波资金攻击了哪些方向？
2. 哪些首板具备次日继续观察的价值？
3. 哪些首板只是跟风、套利或弱封，应降低优先级？

## 数据源方案

首版数据源优先使用腾讯财经。

腾讯财经适合先完成 A 股助手的行情验证和收盘后复盘，重点获取：

- A 股基础行情。
- 当日涨跌幅、收盘价、成交额、换手率。
- 分时行情，用于推导首次涨停时间、炸板次数和回封情况。
- 个股基础信息，用于排除 ST、新股未开板等特殊样本。

腾讯财经可能需要补足的数据：

- 精确封单金额。
- 题材概念归属。
- 涨停原因。
- 连板高度的历史确认。

补足方案：

- 首板识别、炸板次数和封板时间优先通过腾讯分时数据推导。
- 题材概念可以先用行业字段兜底，后续再接同花顺问财、东方财富概念或本地题材库。
- 连板高度通过历史交易日涨停结果递推，不强依赖外部涨停池。
- 精确封单金额如果腾讯接口不可稳定获取，初版先用“封板时间 + 炸板次数 + 成交额 + 收盘是否封死”做替代评分。

## 首板定义

首板指当日涨停，且最近连续涨停天数为 1 的个股。

基础排除项：

- 排除 ST、*ST、退市整理股。
- 排除新股上市未开板阶段。
- 排除北交所，除非后续明确纳入。
- 默认以 A 股主板、创业板、科创板为范围。

涨停价格口径：

- 主板通常按 10% 涨跌幅。
- 创业板、科创板通常按 20% 涨跌幅。
- 特殊处理需要根据交易所规则和个股状态补充。

## 数据字段

### 基础字段

- `trade_date`: 交易日期
- `symbol`: 股票代码
- `name`: 股票名称
- `board`: 所属市场或板块
- `industry`: 行业
- `concepts`: 题材概念
- `close`: 收盘价
- `pct_chg`: 当日涨跌幅
- `turnover_amount`: 成交额
- `turnover_rate`: 换手率
- `free_float_market_cap`: 流通市值

### 涨停字段

- `limit_up_price`: 涨停价
- `first_limit_time`: 首次封板时间
- `last_limit_time`: 最后封板时间
- `open_limit_count`: 炸板次数
- `is_limit_up_close`: 是否涨停收盘
- `limit_up_days`: 连板高度，首板为 1

### 强度字段

- `seal_amount`: 封单金额
- `seal_ratio_amount`: 封单金额 / 当日成交额
- `seal_ratio_float_cap`: 封单金额 / 流通市值
- `limit_open_duration`: 炸板累计时长
- `auction_strength`: 竞价强度，可后续补充
- `strength_score`: 综合封板强度分

如果腾讯财经无法稳定提供封单金额，`seal_amount` 可先设为空，`strength_score` 改用替代评分。

### 复盘字段

- `theme_rank`: 所属题材当日强度排名
- `is_leading_theme`: 是否属于当日主线题材
- `next_day_watch`: 是否进入次日观察池
- `watch_reason`: 入池原因
- `risk_tags`: 风险标签

## 核心指标口径

### 成交额

成交额用于判断资金参与度。首板排序中建议保留两个视角：

- 绝对成交额：识别市场核心容量票。
- 成交额 / 流通市值：识别资金攻击强度。

### 封板强度

初版优先采用腾讯财经可推导的简化评分：

```text
strength_score =
  时间分
  + 封死状态分
  + 炸板惩罚
  + 成交额权重
  + 题材权重
```

建议规则：

- 早盘快速封板加分。
- 收盘封死加分。
- 炸板次数多扣分。
- 尾盘回封降权。
- 属于当日强题材加分。
- 后续拿到可靠封单金额后，再加入封单金额占比。

### 炸板率

模块层面统计两个炸板率：

- 市场首板炸板率：当日曾涨停但未封死的首板数量 / 当日曾涨停首板数量。
- 个股炸板标记：个股当日是否打开涨停，以及打开次数。

这两个指标分别用于判断市场环境和个股质量。

## 次日观察池规则

初版可以采用规则入池，不直接给买卖建议。

入池条件示例：

- 当日首板且涨停收盘。
- 成交额达到设定阈值，例如 3 亿以上，可配置。
- 封板强度分进入前 30%。
- 所属题材当日有至少 2 只以上涨停。
- 炸板次数不超过 1 次。

降权或排除条件：

- 尾盘偷袭封板。
- 多次炸板后弱回封。
- 成交额过小且无明显题材联动。
- 高位股补跌环境下的孤立首板。
- 大幅缩量一字且无法判断换手质量。

## 模块输出

### 每日首板列表

按封板强度、成交额、题材热度综合排序。

### 题材分组

按概念或行业聚合：

- 题材名称
- 首板数量
- 总涨停数量
- 核心首板
- 最高连板高度

### 炸板统计

- 当日首板数量
- 曾涨停首板数量
- 炸板数量
- 炸板率
- 回封数量

### 次日观察池

输出字段：

- 股票代码
- 股票名称
- 所属题材
- 成交额
- 首封时间
- 炸板次数
- 封板强度分
- 入池原因
- 次日观察重点

## 初版开发建议

第一阶段先做离线复盘，不直接做实时交易提醒。

建议流程：

1. 交易日收盘后从腾讯财经拉取当日行情和分时数据。
2. 根据涨停价和分时数据识别曾涨停、收盘封死、首次封板和炸板次数。
3. 通过历史涨停结果递推连板高度，筛出首板。
4. 计算成交额、封板强度、炸板率。
5. 生成次日观察池。
6. 输出为 Markdown、CSV 或前端页面。

## 待确认问题

- 腾讯财经具体接口是否能稳定覆盖全 A 行情和个股分时。
- 题材数据是先用行业兜底，还是同步建立本地题材库。
- 是否需要盘中实时监控，还是先做收盘后复盘。
- “北京炒家”体系中，容量票和小票的成交额阈值是否分开设置。
- 次日观察池只做候选，还是进一步输出竞价观察条件。
- 是否需要记录次日表现，用于回测首板质量。
