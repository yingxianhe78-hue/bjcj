# 北京炒家强化版闭环设计

## 目标

在现有 `首板复盘 -> 次日 9:25 观察池 -> Markdown 报告` 的基础上，补齐盘中跟踪、收盘结果回填、归因和统计，让观察池从一次性输出升级为可迭代修正的闭环系统。

本设计聚焦强化版闭环：

- 保留现有盘前流程。
- 增加盘中 `9:35`、`10:00`、`10:30`、`14:30` 四个固定时点快照。
- 增加收盘结果记录，采用“客观价格行为 + 主观强弱标签”的混合口径。
- 增加“固定词表 + 允许补充”的多标签归因。
- 增加日报和周报统计。
- 增加基于统计结果的规则加权、降权和剔除机制。

不包含的内容：

- 不做自动买卖建议。
- 不做实盘交易执行。
- 第一阶段不做更多盘中时点，也不接入更复杂的盘口微观数据。

## 当前基础

当前仓库已具备这些模块：

- `scripts/build_first_board_review.py`
- `scripts/morning_watch_925.py`
- `bjcj/review/first_board_pipeline.py`
- `bjcj/review/morning_watch.py`
- `bjcj/review/tencent_finance.py`
- `bjcj/review/markdown_report.py`

当前产出链路已经能完成：

1. 首板复盘与观察对象整理。
2. 次日 `9:25` 观察池生成。
3. 腾讯财经实时行情拉取。
4. Markdown 报告生成。

缺口主要在于：

1. 盘中没有结构化过程记录。
2. 收盘后没有统一的结果回填模型。
3. 观察判断无法系统性验证。
4. 周度复盘无法量化哪些因子有效、哪些因子失效。

## 闭环目标定义

闭环定义为：

`首板复盘 -> 次日观察池 -> 盘中过程记录 -> 收盘结果回填 -> 多标签归因 -> 周度统计 -> 反向修正观察规则`

成功标准：

1. 每只进入观察池的股票，都能在盘前、盘中、收盘三个阶段形成统一记录。
2. 每日能输出闭环日报，包含层级表现、盘中转强/转弱和高频归因。
3. 每周能输出闭环周报，展示层级命中率、归因标签表现和规则有效性变化。
4. 后续的 `9:25` 分层规则可以根据周报进行显式修正，而不是靠主观记忆。

## 数据模型设计

### 统一主键

所有记录以以下组合标识唯一对象：

- `trade_date`
- `symbol`
- `session`

其中：

- `trade_date` 为交易日。
- `symbol` 为股票代码。
- `session` 为观察批次，第一阶段固定为 `morning_watch_925`。

### 盘前观察记录

盘前观察记录基于当前 `9:25` 观察池扩展，建议字段如下：

- `trade_date`
- `symbol`
- `name`
- `session`
- `watch_level`
- `open_premium_pct`
- `current_pct_925`
- `turnover_amount_925`
- `yesterday_first_seal_time`
- `yesterday_broken_board`
- `watch_reasons`
- `source_review_date`

说明：

- `watch_level` 取值为 `强观察`、`正常观察`、`降级`、`风险`。
- `watch_reasons` 保留当前规则生成原因，作为后续归因的参照输入。

### 盘中快照记录

新增固定时点快照，每只票在以下时点记录一条数据：

- `09:35`
- `10:00`
- `10:30`
- `14:30`

每条盘中快照建议字段：

- `trade_date`
- `symbol`
- `session`
- `snapshot_time`
- `price_change_pct`
- `change_vs_open_pct`
- `turnover_amount`
- `hit_limit_up`
- `sealed_limit_up`
- `broken_limit_up`
- `subjective_state_tags`
- `snapshot_note`

说明：

- `subjective_state_tags` 允许多个标签，第一阶段建议从固定词表中选择。
- `snapshot_note` 为简短文字补充，只用于说明例外情况，不作为核心统计维度。

### 收盘结果记录

收盘结果采用混合口径，分为客观结果和主观结果。

客观字段：

- `trade_date`
- `symbol`
- `session`
- `high_pct`
- `close_pct`
- `close_turnover_amount`
- `hit_limit_up`
- `sealed_limit_up`
- `broken_limit_up`
- `has_next_day_watch_value`

主观字段：

- `subjective_outcome_tags`

建议的主观结果标签：

- `超预期`
- `符合预期`
- `低于预期`
- `弱转强`
- `冲高回落`
- `全天弱势`

### 归因记录

归因允许多标签，并采用“固定词表 + 自定义补充”模式。

建议将归因标签分为五类：

1. 竞价类
   - `竞价强`
   - `竞价弱`
   - `高开超预期`
   - `低开低于预期`
2. 承接类
   - `承接强`
   - `承接弱`
   - `分时抗跌`
   - `冲高回落`
3. 板块类
   - `板块带动`
   - `板块回流`
   - `板块拖累`
   - `题材掉队`
4. 板型类
   - `炸板修复`
   - `封板犹豫`
   - `抛压大`
   - `弱转强失败`
5. 辨识度类
   - `辨识度高`
   - `跟风属性`
   - `独立走强`

归因记录建议字段：

- `trade_date`
- `symbol`
- `session`
- `attribution_tags`
- `custom_attribution_tags`
- `attribution_note`

约束：

- `attribution_tags` 只允许使用固定词表。
- `custom_attribution_tags` 用于少量特殊情况补充。
- 周度复盘时需要检查高频自定义标签，决定是否吸收进固定词表。

## 数据流设计

### 阶段一：盘前生成观察池

沿用现有 `morning_watch_925` 逻辑，输出盘前观察数据和 Markdown 报告。

输出：

- 结构化盘前观察记录
- 盘前 Markdown 盯盘报告

### 阶段二：盘中固定时点采样

在四个固定时点拉取观察池标的实时行情，并生成结构化快照记录。

输出：

- `09:35` 快照
- `10:00` 快照
- `10:30` 快照
- `14:30` 快照

原则：

- 不在盘中做买卖建议。
- 快照只用于记录状态变化和后续归因。

### 阶段三：收盘结果回填

收盘后读取当日观察池和最后行情，计算每只票的客观结果，并结合盘中快照生成主观结果标签。

输出：

- 收盘结果数据
- 日度闭环结果摘要

### 阶段四：归因回填

根据盘前判断、盘中过程和收盘结果，为每只票记录多标签归因。

实现方式建议：

- 先规则化自动生成候选归因标签。
- 再允许人工补充或修正少量标签。

这样既能降低维护成本，也能保留盘感判断。

### 阶段五：日报和周报统计

日报关注当天反馈，周报关注规则有效性变化。

日报建议指标：

- 各观察层级数量与表现
- 从 `强观察` 到收盘结果的偏差
- 盘中由弱转强的股票
- 高频成功归因标签
- 高频失败归因标签

周报建议指标：

- `强观察`、`正常观察`、`降级`、`风险` 的成功率对比
- 四个盘中时点中，哪些时点的转强信号最有效
- `炸板修复`、`板块带动`、`竞价强` 等标签的近一周表现
- 最近失效的规则和最近增强的规则

## 成功口径定义

为了能稳定统计，需要明确什么叫“成功”。

第一阶段建议定义多个统计口径，而不是只保留单一口径：

- `close_positive`: 收盘涨幅大于 `0`
- `strong_close`: 收盘涨幅达到指定阈值
- `hit_limit_up`: 日内摸板
- `sealed_limit_up`: 收盘封板
- `outperform_expectation`: 主观标签包含 `超预期` 或 `弱转强`

这样后面可以按不同风格查看结果，而不需要改底层数据结构。

## 反向修正规则

周度统计之后，只做三类规则调整：

1. 加权
   - 最近一周表现稳定有效的信号，提高在 `9:25` 观察分层中的权重。
2. 降权
   - 最近连续走弱的信号，降低优先级。
3. 剔除
   - 连续多周无效且没有结构性原因支撑的信号，暂时移除。

规则修正需要有据可查，因此每次调整都应记录：

- 调整日期
- 调整对象
- 调整类型
- 触发原因
- 观察周期

## 模块拆分建议

建议在现有结构基础上新增以下能力模块：

- `intraday_snapshots`
  - 负责固定时点行情采样和快照落盘。
- `close_results`
  - 负责收盘结果计算和客观结果汇总。
- `attribution`
  - 负责归因标签生成和人工补充入口。
- `stats`
  - 负责日报和周报统计。

保持原则：

- 盘前、盘中、盘后逻辑分离。
- 数据采集、规则判断、报告渲染分离。
- 所有报表均来自结构化数据，而不是直接拼接临时文本。

## 输出物建议

第一阶段建议形成以下输出物：

1. 结构化数据
   - 当日观察池记录
   - 盘中快照记录
   - 收盘结果记录
   - 归因记录
2. 报告
   - 盘前盯盘报告
   - 日度闭环报告
   - 周度闭环报告

## 风险与控制

### 风险一：标签体系失控

如果允许过多自由标签，后续统计会失真。

控制方式：

- 固定词表优先。
- 自定义标签限制数量。
- 每周清理和吸收高频标签。

### 风险二：盘中采样过重

盘中时点过多会提高维护和执行成本。

控制方式：

- 第一阶段固定 4 个时点，不再增加。
- 只有当统计证明需要更细粒度时，再扩展时点。

### 风险三：主观标签漂移

同一标签被不同语义使用，会导致统计失真。

控制方式：

- 为主观结果标签和归因标签建立明确释义。
- 周报中检查标签使用一致性。

## 测试与验证思路

第一阶段实现后，至少验证以下内容：

1. 盘前观察池和盘中快照能按统一主键正确关联。
2. 四个时点快照都能在缺少个别行情字段时稳健运行。
3. 收盘结果计算逻辑可重复，不依赖手工编辑。
4. 归因标签在固定词表和自定义补充之间能正确区分。
5. 日报和周报统计能从结构化数据完整生成。

## 第一阶段范围界定

为了保证可落地，第一阶段只实现这些内容：

1. 固定 4 个盘中时点快照。
2. 收盘结果混合口径记录。
3. 多标签归因结构。
4. 日报和周报统计。

暂不实现：

1. 分钟级连续监控。
2. 自动交易或提示。
3. 更复杂的盘口明细分析。
